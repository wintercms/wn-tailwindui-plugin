Winter core — role-first colour consolidation

A re-cut of the light-mode palette proposal. The previous pass grouped colours by what they look like today; this one groups them by the job they do, because two colours that match in light mode still have to move apart in dark mode.

Why this differs from the value-clustered proposal. There, --wn-bg (“page background”) absorbed @body-bg and @table-bg-accent — the page canvas and the table zebra stripe — because both are #f9f9f9 today. The shipped dark skin already paints them #0d1117 and #0c121a: identical in light, deliberately different in dark. Welded into one token, zebra striping flattens and disappears the moment dark mode becomes a token redefinition — which is the whole point of step D.

Dark needs 34 distinct surface values; light spreads 81 across 8 elevation tiers. Collapse the tiers and dark mode can no longer be expressed by redefining tokens — it falls back to per-element overrides, the 64 KB of darkmode.css this exercise exists to delete.

The model — two tiers

Collapsing values is safe and reversible. Collapsing roles is neither. So the base palette holds the literal values, and each semantic token names a job and points at one. Two roles may share a base value today and still be redefined independently later — a one-line change instead of a re-audit.

Proposed semantic tokens

One per job. The canonical value is the most-used within that role; click any value to choose a different one. A role carrying many values is not necessarily wrong — it may just span several components that genuinely agree.

Values serving more than one role

These are the merges the previous grouping would have made. Each of these values does several unrelated jobs; they stay as separate tokens that happen to resolve to the same base today.
